# Schema v1

This document describes the initial storage contract. Schema v1 is intentionally created before external importers so source-specific quirks can be tested against a clear baseline rather than silently shaping the database.

## Runtime database: `timestamps.db`

### `metadata`

Database role, schema version, and project identifier.

### `sources`

Logical import origins such as `baha`, `open-anime-timestamps`, or `aniskip`.

A source answers: **where did we read this record from?**

### `lineages`

Independent timing-evidence producers.

A lineage answers: **whose observation is this really?**

Sources and lineages are deliberately separate. An aggregator can import a record whose lineage belongs to another provider. Consensus logic must count independent lineages rather than mirrors.

### `titles` and `title_ids`

`titles` is a lightweight local identity used only inside the compiled timestamp database. `title_ids` exposes provider/ID pairs for lookup.

The timestamp project does not replace `anime-mapping-db`. Future builders should use a pinned mapping database/release to normalize title identities, then copy only the identifiers needed for timestamp lookup into `timestamps.db`.

### `episodes`

An episode belongs to one local title and has an opaque `episode_key`.

The key is the primary normalized identity inside the timestamp database. Optional fields such as `episode_number`, `season_number`, and `season_episode_number` are helpers, not the identity itself. This allows importers to represent ordinary episodes, specials, fractional numbering, and season-scoped numbering without a schema change.

### `episode_refs`

Maps source-specific opaque episode keys to normalized episodes. The source-specific key may later be a native episode ID or a deterministic composite generated by an importer.

### `segments`

One normalized timestamp observation.

Important fields:

- `episode_id`
- `source_id`
- `lineage_id`
- `source_segment_id`
- `segment_type`
- `start_ms`
- `end_ms`
- optional normalized `confidence`
- `is_derived`

All runtime times are integer milliseconds. Importers must preserve higher-level upstream metadata in evidence records where necessary.

`segment_type` is open text rather than a SQL enum. Importers will normalize common values but unknown future types must not force a migration merely to be stored.

### `consensus_segments` and `consensus_members`

Consensus is materialized derived data, not a replacement for source observations.

Each consensus range records the algorithm and tolerance used. `consensus_members` links the result back to every contributing runtime segment. `lineage_count` represents independent evidence lineages and is intentionally distinct from `member_count`.

No consensus algorithm is implemented in schema v1 yet. Real source overlap must be measured first.

## Evidence database: `timestamps-evidence.db`

The evidence database is outside the hot runtime lookup path.

### `source_snapshots`

Records one imported upstream snapshot with URL, version, SHA-256, retrieval time, license note, record count, and additional JSON metadata.

### `records`

Records the upstream record key, original lineage, source title/episode references, and an optional payload hash.

### `record_segments`

Stores the normalized segment values observed in a specific upstream record so a runtime row or future consensus result can be audited against the imported source snapshot.

## Deliberate omissions from v1

Schema v1 does not yet define:

- HTTP/API client state;
- crawler checkpoints;
- request caches;
- votes/reactions tied to one specific service;
- provider-specific JSON columns in the runtime database;
- a fixed segment-type enum;
- a consensus algorithm;
- release manifests.

Those concerns should be added only after real bulk datasets have been imported into throwaway validation builds and the generic model has been proven insufficient.

## Filename convention

The project uses `timestamps.db`, not `timestamps.sqlite3`, solely for consistency with `anime-mapping-db` and its `mappings.db` artifact. Both extensions describe the same SQLite file format; SQLite itself does not require either one.
